# Distributor-Retailer Management System

A backend system for managing distributor and retailer operations, including product inventory and order processing.

The project follows a **microservices and event-driven architecture**, where the Order Service communicates with the Inventory Service and publishes events through Apache Kafka.

## Overview

The main goal of this project is to understand how independent backend services can communicate with each other and how **Kafka-based event-driven communication** can be used in a real-world application.

### Current Flow

```text
Retailer
   |
   v
Order Service
   |
   | REST API
   v
Inventory Service
   |
   | Inventory Update
   v
Kafka Event
   |
   v
Notification / Event Consumer
```

## Features

* Create and manage products
* Maintain product inventory
* Create customer/retailer orders
* Validate order items
* Check product availability before confirming an order
* Update inventory after successful order processing
* Publish order/inventory events using Apache Kafka
* RESTful APIs
* DTO-based request and response handling
* Bean Validation
* Centralized exception handling
* JPA/Hibernate for database operations
* MySQL database integration

## Architecture

The project separates responsibilities into independent services.

### Order Service

Responsible for:

* Creating orders
* Managing order items
* Calculating order totals
* Validating order requests
* Communicating with the Inventory Service
* Publishing order-related events

### Inventory Service

Responsible for:

* Managing products
* Maintaining available stock
* Checking product availability
* Updating inventory after an order

### Notification / Event Service

Responsible for consuming Kafka events generated by other services.

This service demonstrates asynchronous communication between backend services.

## Order Processing Flow

When a retailer creates an order:

```text
1. Client sends order request
        |
        v
2. Order Service validates request
        |
        v
3. Order Service checks inventory
        |
        v
4. Inventory Service verifies stock
        |
        v
5. Order is processed
        |
        v
6. Inventory is updated
        |
        v
7. Kafka event is published
        |
        v
8. Event consumer receives the event
```

## Kafka

Apache Kafka is used for asynchronous communication between services.

Instead of making every operation synchronous, important events can be published to Kafka topics and consumed by other services.

Example:

```text
Order Service
      |
      | Order Created Event
      v
   Kafka Topic
      |
      +------------------+
      |                  |
      v                  v
Notification       Other Consumers
Service
```

This approach helps demonstrate the fundamentals of **Event-Driven Architecture (EDA)**.

## Running the Project Locally

### Prerequisites

Make sure the following are installed:

* Java 21
* Maven
* MySQL
* Apache Kafka
* Apache Kafka dependencies / broker setup

Check Java version:

```bash
java -version
```

Check Maven:

```bash
mvn -version
```

### Database Configuration

Create a MySQL database:

```sql
CREATE DATABASE drms_db;
```

Configure the database connection in the respective service's `application.properties` or `application.yml`.

Example:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/drms_db
spring.datasource.username=root
spring.datasource.password=your_password

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
```

Use your local credentials instead of the example values.

## Starting Kafka

Make sure the Kafka broker is running before starting services that publish or consume Kafka events.

The Kafka configuration should match the broker address configured in the application.

Example:

```properties
spring.kafka.bootstrap-servers=localhost:9092
```

## Start the Services

Run each service from its respective directory:

```bash
mvn spring-boot:run
```

Or build the project first:

```bash
mvn clean package
```

Then run the generated JAR:

```bash
java -jar target/<service-name>.jar
```
